# AgentRouter Go proxy: preliminary Linux evaluation

**Reviewed:** 2026-11-03. Source: [trefeon/agentrouter-spoof-proxy](https://github.com/trefeon/agentrouter-spoof-proxy), commit [`afa0be17622f95c276d447ab45decb6a049095a7`](https://github.com/trefeon/agentrouter-spoof-proxy/tree/afa0be17622f95c276d447ab45decb6a049095a7). Scope: targeted source and documentation review, not a full security audit. The checkout was inspected in a temporary directory, not installed into OWL.

## Findings

- **Broad API surface:** [route registration](https://github.com/trefeon/agentrouter-spoof-proxy/blob/afa0be17622f95c276d447ab45decb6a049095a7/internal/server/server.go) includes Anthropic Messages, OpenAI Chat Completions and Responses, embeddings, image and audio routes. Local token counting and model retrieval also exist. A registered route does not guarantee support for every payload or upstream model.
- **Resilience:** the code has WAF-cookie storage, a circuit breaker, model health and background probing, and SSE handlers. Its [.env example](https://github.com/trefeon/agentrouter-spoof-proxy/blob/afa0be17622f95c276d447ab45decb6a049095a7/.env.example) documents transport retries by default and optional 5xx retries. Replaying requests can cause duplicate charges; test retry semantics against your provider before use.
- **Local security:** default listen address is `127.0.0.1`; `PROXY_AUTH_TOKEN` is optional. Health and model-list endpoints remain open. Dashboard and proxy requests use the token gate, but no token is required by default; localhost does not isolate mutually untrusted local processes.
- **Separate upstream and proxy credentials:** [auth logic](https://github.com/trefeon/agentrouter-spoof-proxy/blob/afa0be17622f95c276d447ab45decb6a049095a7/internal/server/server.go) accepts a local token via bearer Authorization or `X-Proxy-Token`. The [request handler](https://github.com/trefeon/agentrouter-spoof-proxy/blob/afa0be17622f95c276d447ab45decb6a049095a7/internal/proxy/handler.go) forwards incoming Authorization and `x-api-key` upstream. Therefore, if using distinct proxy and upstream bearer tokens, send the proxy token using `X-Proxy-Token` and the upstream credential using Authorization, **provided the client supports both headers**. A local token placed in Authorization may be forwarded to the upstream; test the chosen client without real secrets first. Do not assume one bearer token can serve both purposes.
- **Behavioral changes:** an engineering-framing system prompt is injected by default; set `INJECT_SYSTEM_PROMPT` to the empty string to disable it, ensuring the environment variable is actually present. OpenAI-format thinking-tag stripping is enabled by default. Review both before use.
- **Resource limits:** the source caps proxied request bodies at 20 MiB and documents a body-upload deadline. `REQUEST_TIMEOUT_MS` is documented as parsed but unused; other header and stream timeouts apply. Limits and stream behavior were not independently runtime-tested.
- **Lifecycle/deployment:** the project documents Linux Docker/systemd options, and its Go source includes graceful shutdown. Its `go.mod` requires Go 1.26.5; Go and Docker/Podman were not available in this environment, so its build, tests and binary were **not run**. No scripts from that repository were executed.

## Recommendation and next decision

For broad API coverage the Go proxy is the stronger **candidate**, not yet a verified replacement. Keep OWL's existing stack untouched and run the proxy as a separate, explicitly configured service if a trial is approved. Choose the OWL bridge instead only if an integrated Anthropic-only sidecar is the priority, then execute the hardening plan in [the assessment](superpowers/plans/2026-11-03-agentrouter-assessment.md).

Before adoption, run the Go project's tests in an isolated environment with its required toolchain; test auth/header separation, streaming, disconnects, limits and prompt transformation with a mock upstream. Then, only with authorized credentials and provider approval, run equivalent small live streaming and non-streaming requests against the same model and account. Record versions, status and limitations without logging keys or prompts. Provider policy, account entitlements and upstream behavior may change; no 401, 403 or 503 alone proves a particular WAF or capacity diagnosis.

Confidence in the broad-API candidate recommendation: **70/100**, a subjective assessment based on source-level coverage, reduced by the lack of build, runtime and live verification.
